# Current architecture overview

- **Status**: Current (verifiable against the repository and tests)

## Components

```text
Host (Cordis plugin, src/index.ts + src/service.ts)
  requires ctx.subprocess; provides ctx.git
  git executable + separate argv; never a shell
  optional Connection child fiber: loopback /git RPC
    |
    | status / diff / log / stage / commit / branch ...
    |
Client (src/client/)
  main fiber: every portable contribution
    composer branch picker and changed-file indicator through slots
    permanent sidebar tab types: git.changes / git.diff / git.graph
    capability-dependent git.worktrees
    git-commit-message and git-worktrees settings cards
      (compatibility: individual cards or combined bundle details)
    advisory commit-message generation using the Host LLM runtime
  ctx.inject(['desktop']) child: reveal / openPath / notifications
```

## Structural facts

- **Host service**: Launches Git through `ctx.subprocess`, using an executable name or absolute path and separate argv values. Each command runs in the caller's repository, or the checkout containing the session's effective directory when the Host supplies directory services and the session has a live agent. It never uses process-wide `process.cwd()`. Status uses porcelain v2 with NUL-delimited paths; branches use `for-each-ref`; history uses paginated `git log` with the fixed-field `GIT_LOG_FORMAT` for progressive Graph loading. Checkout kind and `git worktree list --porcelain -z` results accompany status. NUL-delimited paths retain leading and trailing whitespace; older Git falls back to newline output. Discard uses explicit index/worktree/clean operations and requires two-step Client confirmation.
- **Session directory**: The Client uses a nonempty projected `workingDirectory`, otherwise the session header's `cwd`. It consumes the existing Host projection without a separate directory database. Directory changes cancel old reads and unsent writes. An already-sent worktree creation waits independently for its receipt so its own directory projection cannot cancel the successful result; controller disposal still cancels it. Other in-flight Git RPCs follow binding cancellation. Host writes also verify that the requested repository matches the effective directory's checkout; mismatches fail rather than applying results to another checkout. Each session has its own controller.
- **Worktree boundary**: The plugin discovers every checkout of a repository regardless of origin. With `workingDirectory.set` and a live session agent, the user can move the current session into another listed checkout. The `git.worktrees` sidebar type follows `worktree-capability`: `upstream` delegates creation to the experimental Host `ctx.worktrees.create(agent, ...)`, which changes the session directory on success; the UI follows the projection. Without that runtime, enabled `git-worktrees` settings select `local`: `GitService.createWorktree` runs `git worktree add -b`, defaulting to `<repository>/.agents/worktrees/`, then enters through session directory services. Optional `ctx.fs` only checks occupancy and maintains the pool's `.gitignore` marker. Otherwise mode is `off` and the type unregisters. Capability is read on mount and every five seconds; settings saves refresh immediately, with one trailing poll after an in-flight read. Registrations and session controllers share the capability store, allowing mode/provider changes without rebinding. Unload stops timers and subscriptions. Absolute pool paths, including Windows UNC/root paths, are preserved; relative paths resolve against the repository. Upstream probing is structural (`create` exists), with no experimental-package dependency. Deletion/pruning are outside scope. Directory changes and creation serialize, keeping entry buttons disabled while queued work remains.
- **RPC**: When the DSH Web Host exists, a Connection child fiber registers the loopback `/git` channel. Stale mutation results are discarded; filenames use literal pathspecs.
- **Client refresh merging**: `GitClientController.refresh()` shares in-flight work for the same path and `operationGeneration`, releasing the slot in `finally`. A request arriving before status starts shares that read. A request arriving after status starts schedules one trailing read; merged callers await it even if the first read failed. A burst contains at most two rounds, preventing feedback from Windows console focus events generated by the controller's own Git commands. Composer `window` focus handlers therefore avoid stacked discover/status rounds and mutually superseding results. See [troubleshooting](../troubleshooting/windows-desktop-console-flood.md).
- **Client tab caching**: Changes/Worktrees no longer force an extra refresh on mount. Surfaces share `setWorkspace`, reusing session snapshots for five seconds and retaining content while refreshing on a stale return. Explicit refresh and mutations bypass freshness gates. Graph retains loaded history until repository refresh or mutation invalidates it. Each path/side Diff caches for at most five seconds, with at most 32 entries per session. Repository snapshot replacement, workspace rebinding and `navigation.revision` changes invalidate the relevant result; errors are not cached. Remote views have a longer freshness window and conditional page updates; their sole policy reference is the [remote-platform RPC contract](../reference/remote-platform-rpc.en.md#client-caching-and-incremental-validation-current). All caches live in the current Client memory and do not survive restart.
- **Right sidebar integration**: The Client manifest declares `ctx.sidebarRight` / `ctx.sidebarRightTabs` through `inject`. Sidebar package imports are type-only: dynamic plugins must not import runtime values from other packages, so erased types require no bundle external. Phase one registers permanent Changes/Graph page types and the Diff resource type (`dsh-resource://git/diff/**`). Worktrees registers/unregisters with capability mode; fiber unload unregisters it. Remote list page and item resource types (`dsh-resource://git-remote/<owner>/<repo>/<kind>/<number>`) follow remote capability on/off. Phase two injects bodies into `sidebar.right.pane.tab`, keyed by definition id. Navigation uses `ctx.sidebarRight.openTab(kind)` and `openResource(address, { params })`. Changes/Graph deduplicate by kind within each pane; Diff and remote items use exact resource addresses. Reopening reveals the existing tab and increments `navigation.revision`; payload types augment `SidebarRightResourceParamsMap`. The upstream sidebar, based on ui-dockkit, owns the tab bar, guide, docking geometry and panel widths. Diff results remain panel-local: `fetchDiff` independently caches each path/staged side and shares in-flight reads, while each surface owns its request/result projection keyed by repository root and tab address. Out-of-order results cannot cross split panes, floating windows or staged/worktree tabs. Changes/Graph/Worktrees register live titles in `sidebar.right.pane.tab.title`; Diff chips use language-independent filenames and remote item chips derive `PR #n`/localized Issue labels from addresses, so neither registers that slot. Open chips track locale changes. Provider unload removes registrations while preserving tab records; upstream shows its unavailable fallback until registration returns.
- **Diff presentation**: `GitDiffSurface` handles fetching, panel state and sidebar adaptation; the official `@deepseek-ai/dsh-client-ui-primitives` `DiffBlock` owns rendering. `git-diff-adapter.ts` uses the existing `diff` package's `parsePatch` to produce old/new text fragments. Display paths use the selected literal filename rather than quoted Git headers. Copy, folding and newer Host newline controls belong to the official component. Worktree/index/HEAD comparisons never become session-turn snapshots. Binary files, metadata-only changes, empty patches and incomplete patches have separate states. Because the component normalizes line endings, the adapter tracks missing terminal newlines and shows a notice only when the two sides differ; both missing, including shared-context markers, is not a difference. Context/label compatibility lives in `src/compat/dsh-diff.ts`; see the [compatibility reference](../reference/dsh-compatibility.md#官方-diffblock-接入).
- **Remote platform (ADR-0004)**: The credentials child fiber in `src/remote/` owns auth/refresh, REST, account caches and cancel/drain. RPCs are available only with a complete seam; missing/incomplete seams turn the whole feature off. Capability performs no network/subprocess work; storage, auth, viewer and permission states remain independent. The Client main fiber dynamically registers the remote list page/body/title and shared PR/Issue resource body. The list offers filters and PR creation; item details, discussion, file comparison and guarded writes open in address-identified detail tabs. Authentication sits in a toolbar-icon dialog. Scoped protocol and GitLab instances use separate providers and a registry; GitLab Host reads, local Git, guarded remote writes and the portable Client passed automated stage verification, and removed-instance grants can be retired through storage only. Native notifications are an unloadable enhancement. Checkout uses private refs, SHA verification, tracking CAS and partial receipts; OAuth never enters Git transport. Models/coordinates remain browser-safe, and local structural types support older lanes without the optional seam package. Published optional peers use registry ranges. The [remote-platform RPC contract](../reference/remote-platform-rpc.en.md) is authoritative; stages and outstanding real OAuth/platform/matrix acceptance live in the [plan](../plans/active/remote-platform-integration.en.md).
- **Portable/native split**: The main fiber never requires `desktop`. The optional child consumes only `shell.showItemInFolder`, `shell.openPath` and `notification.show`. Core operations remain available without Desktop; native actions are hidden.
- **Graph layout engine** (`src/client/graph/`): Pure logic with no Git, React or DOM access, independently testable and separate from Canvas rendering. See [Git Graph Layout Engine](../reference/git-graph-layout.md), [ADR-0001](../decisions/ADR-0001-graph-lane-not-owned-by-branch.md) and [ADR-0002](../decisions/ADR-0002-graph-lane-cap-max-three-lanes.md).
- **Commit-message generation**: An independent Host LLM request outside session context, with no KV-cache impact. It requires an LLM runtime and resolvable model; otherwise the Client reports `git/generation-unavailable`. Configuration is canonical in the root README's [Configuration](../../README.md#configuration).
- **Loading/cancellation recovery**: Mounting the same directory does not rebind because refresh changed a result generation. Successful refresh updates session capabilities. The Host caches only successful Git executable discovery; cancellation and lookup failure do not poison subsequent requests. Changes/Graph expose discover/status errors. See [Git blank UI and persistent AbortError](../troubleshooting/git-workspace-abort.md).
- **Settings save**: The bundle page shares one Save button. Sections save sequentially and read the shared ConfigForm's new revision after each completion. Leaving during a save retains the next pending section. Rejected writes/transport errors retain drafts and restore editing/retry. Disabling local mode explicitly writes `false` to override composition defaults.
- **Creation admission**: Upstream Worktrees creation requires current session directory capability, including a live agent, both when opening and submitting the dialog. Local mode can create without a live agent and skip entry. Pool-directory hints appear only in local mode; upstream owns its creation location.
